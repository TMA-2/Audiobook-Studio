# Minimal Audio Sidecar Generation Export Implementation Plan

## Overview
Currently, audio sidecar export duplicates generation entries and audio data for every snippet in a multi-snippet generation range, while also saving redundant metadata (`text`, `speakerId`, `model`, etc.) that is already tracked by `Snippet.generations`. This results in bloated sidecar JSON exports (up to ~1GB for large projects).

This change refactors sidecar generation exports so that each unique audio generation is exported only once with minimal required fields:
- `id`: string
- `snippetId`: string[] (array of snippet IDs sharing this generation)
- `audioMimeType`: string
- `duration`?: number (optional)
- `data`: string (base64 audio payload)

## Proposed Changes

### 1. `src/utils/sidecarExporter.ts`
- Update `SidecarGenerationItem` interface to reflect minimal properties:
  ```typescript
  export interface SidecarGenerationItem {
    id: string;
    snippetId: string[];
    audioMimeType: string;
    duration?: number;
    data: string;
  }
  ```
- Refactor `exportSidecarStream()`:
  - Aggregate unique generation IDs across `project.chapters -> snippet -> snippet.generations`.
  - Collect `snippetId: string[]` associated with each unique generation ID.
  - Fetch audio base64 data from IndexedDB once per unique generation ID.
  - Stream minimal `SidecarGenerationItem` objects to disk or Blob chunk array.

### 2. `src/App.tsx` (`handleImportSidecar`)
- Update sidecar import handler to support both the new array `snippetId: string[]` format and legacy scalar `snippetId: string` format.
- Ensure fallback values when matching/restoring snippet generations if metadata fields (`text`, `speakerId`) are omitted from the minimal sidecar item.

### 3. Unit Tests (`src/utils/sidecarExporter.test.ts`)
- Update `sidecarExporter.test.ts` to test minimal generation items with `snippetId` array formatting and deduplicated stream export.
