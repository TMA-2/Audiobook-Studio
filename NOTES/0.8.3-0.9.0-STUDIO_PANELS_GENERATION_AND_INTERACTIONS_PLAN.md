# Plan: Studio Side Panels, Generation vs Export Settings, and Interactions API Support

**Start Version**: `0.8.3`  
**Target Version**: `0.9.0`  
**Date**: 2026-07-26  

---

## Overview

This plan addresses several key functional and workflow improvements for Audiobook Production Studio:
1. **Collapsible Side Panels**: Making Chapters, Scenes, and Speakers lists in the Studio panel collapsible to prevent UI overflow and scrolling strain in large multi-chapter projects.
2. **Audio Generation Strategy vs Export Strategy**: Splitting the setting into separate controls for:
   - **Export Concatenation Strategy**: How audio files are concatenated when saved to disk (`per-paragraph`, `per-scene`, `per-chapter`, `full-project`).
   - **Audio Generation Strategy**: How API requests are structured (`individual` vs `combined` batching up to 2 speakers / 8KB limit).
3. **2-Speaker Prompt Template Validation & Formatting**:
   - Validation warning when > 2 unique speakers are included in a combined multi-speaker generation request.
   - Dynamic rendering of 1 or 2 speaker template blocks based on unique active speakers.
4. **Interactions API Endpoint Support**:
   - Implementing server-side handler for `useInteractionsAPI` in `server.ts` using `@google/genai` SDK with fallback and parameter handling.

## Detailed Action Items

### Step 1: Collapsible Side Panels in Studio
- In `src/App.tsx`, introduce collapse states:
  - `isChaptersCollapsed`: boolean (default `false`)
  - `isScenesCollapsed`: boolean (default `false`)
  - `isSpeakersCollapsed`: boolean (default `false`)
- Add collapse toggle icons (`ChevronDown` / `ChevronRight`) to the headers of Chapters, Scenes, and Speakers sections in the sidebar.
- Hide the item lists when their section is collapsed, saving vertical space for long project views.

### Step 2: Separate Audio Generation & Export Settings
- In `src/types.ts`:
  - Extend `Project['settings']` with `generationOption?: 'individual' | 'combined'`.
- In `src/components/SettingsDialogue.tsx`:
  - Under Audio/Project settings tab, add an **Audio Generation Strategy** control with options:
    - **Combined snippet generation**: Batches contiguous selected snippets into multi-speaker requests (max 2 speakers / 8KB).
    - **Individual snippet generation**: Sends 1 API request per snippet.
  - Include an inline helper tooltip detailing the 2-speaker and 8KB request payload limits.
- In `src/App.tsx`:
  - Update multi-snippet batching logic (`handleGenerateAudio`) to respect `generationOption`.

### Step 3: 2-Speaker Prompt Compilation & Error Handling
- In `src/utils/promptCompiler.ts` & `src/components/SettingsDialogue.tsx`:
  - Count unique speakers in the target snippet batch.
  - If `uniqueSpeakers.length > 2` and `generationOption === 'combined'`, return an explicit error/warning (`Gemini multi-speaker generation supports up to 2 speakers per request. Please select snippets with at most 2 distinct speakers or switch to individual generation.`).
  - Replace speaker block template placeholders cleanly for 1 or 2 speakers.

### Step 4: Server-Side Interactions API Support
- In `server.ts`:
  - [-] Implement handling when `useInteractionsAPI` is `true`. User has *mostly* handled this, but it needs a once-over because the user is still a TS noob and is very tired from poring over the terrible API documentation.
  - Check `ai.interactions` availability or format request for interactions endpoint.
  - Return compiled audio data, mimeType, and optional interaction metadata.

### Step 5: TDD, Verification & Versioning
- Add test cases covering prompt compiler speaker limit validation and template rendering.
- Verify through `npm run lint` and `compile_applet`.
- Update `CHANGELOG.md` and `package.json` to version `0.9.0`.
