# Plan: Multi-Snippet Generation & Scene Integration

This document serves as the implementation plan and single source of truth for adding multi-snippet generation, scene sidebar controls, prompt template variable interpolation, and robust state/speaker synchronization.

## Target Version: 0.6.3 -> 0.7.0 (Feature Addition)

---

## Stage 1: Core Type & State Synchronization

### 1.1 Type System Extension (`src/types.ts`)
- Add `context?: string` to the `Scene` interface in `src/types.ts`.
- Ensure all types (`Project`, `Speaker`, `Scene`, `Snippet`, `Chapter`) align correctly with the extended properties.

### 1.2 State Sync & Handler Unification (`src/App.tsx`)
- Verify that opening `SettingsDialogue` reads `project.speakers` and `project.scenes` accurately.
- Ensure that clicking "Save" in `SettingsDialogue` calls a centralized handler `updateProjectState` in `src/App.tsx` that commits both speakers and scenes arrays back to the state in a single action, keeping the sidebar and settings in perfect synchronization.
- Fix any potential caching or state mismatch issues during project-level operations (e.g. Markdown imports).

## Stage 2: Scene Parsing & UI Integration

### 2.1 Markdown Importer Extension (`src/services/markdownParser.ts`)
- Implement scene parsing inside chapters using `H3` headings (lines starting with `### `).
- Support syntax like `### Scene: <Name>`, `### Scene - <Name>`, or `### <Name>`.
- Extract subsequent lines following the scene heading as `{scene_description}` and `{scene_context}` (e.g., lines under `### Context`).
- Assign all subsequent snippets parsed in that chapter to this parsed Scene's `id` until a new scene heading or chapter heading is encountered.

### 2.2 Scene Selection list in Sidebar (`src/App.tsx`)
- Add an "Acoustic Scenes" section in the sidebar below or above the "Speakers" section, styled identically to the "Speakers" section.
- Allow clicking a scene to assign it to the focused snippet, or to bulk-assign it to all selected snippets.
- Add an add/edit shortcut that opens the Settings dialogue to the "Scenes" tab.

### 2.3 `SettingsDialogue` Upgrades (`src/components/SettingsDialogue.tsx`)
- Add a new "Scene Context / Narrative Background" textarea box under the "Environmental & Acoustic Instructions" textarea.
- Update the compiled prompt preview renderer (`renderMarkdownPreview`) to replace `{scene_context}` with `activeScene.context`.

## Stage 4: Multi-Speaker API Request Construction & Backend Support

### 4.1 Prompt Template Variables Assembly (`src/App.tsx`)
- When generating a range of snippets:
  - Fill all `{variables}`: `{project_title}`, `{chapter_title}`, `{speaker_name}`, `{speaker_role}`, `{speaker_voice}`, `{speaker_style} or {speaker_instructions}`, `{scene_name}`, `{scene_description}`, `{scene_context}`, and `{snippet_text}`.
  - For single speaker: replace variables with active speaker properties.
  ```markdown
  ## Speakers
  ### {speaker_name}
  - Role: {speaker_role}
  - Voice: {speaker_voice}
  - Style: {speaker_instructions}
  ```
  - For multi-speaker (2 speakers):
    - Use the same speaker template repeated twice under Speakers, e.g.
    ```markdown
    ## Speakers
    ### {speaker_name}
    - Role: {speaker_role}
    - Voice: {speaker_voice}
    - Style: {speaker_instructions}
    <!-- append the next speaker info if defined -->
    ### {speaker_name}
    - Role: {speaker_role}
    - Voice: {speaker_voice}
    - Style: {speaker_instructions}
    ```
    - Separate speakers into their own H3 sections uner `## Speakers` -- *only one or two may be added*
    - Separate style guidelines or roles clearly.
    - It will likely be necessary to add a second, single-line text box for each speaker to define their Role, e.g. "main love interest", "deuteragonist", etc.
    - Replace `{snippet_text}` by appending the speaker name prefix to each line (e.g., `Jane: Hello jane\nCookie: Heya cooky`) and joining them.
  - Verify that the resulting text matches the prompt settings dialogue output exactly with no additional unsolicited wrappers.

### 4.2 Multi-Speaker Voice Config Backend Integration (`server.ts`)
- Update `server.ts` to support receiving multi-speaker settings via `speechConfig.multiSpeakerVoiceConfig`.
- Map each unique speaker name appearing in the segment to their selected prebuilt voice name.
- Fallback gracefully to single speaker voice configuration if only one speaker is detected.
- Verify everything compiles successfully and passes linting checks.
