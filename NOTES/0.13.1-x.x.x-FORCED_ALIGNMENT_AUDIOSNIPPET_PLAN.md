# Plan: Forced Alignment & Per-Snippet AudioSnippet Model

**Start version:** 0.13.1
**Target version:** 0.14.0 (minor bump — new feature, additive/backward-compatible)

## Problem

Audio generations currently cover one-or-more snippets as a single opaque blob (`Generation.snippetId: string | string[]`), keyed to base64 PCM stored in IndexedDB under the `Generation.id`. This means:

- An individual snippet inside a multi-snippet generation cannot be played in isolation without manual seeking.
- A flubbed single line cannot be regenerated and spliced back into an otherwise-good multi-snippet take.
- No word-level timing exists, so there is no way to select a text range and play just that audio, or highlight words during playback.

## Solution

Add [`echogarden`](https://www.npmjs.com/package/echogarden) (pure TypeScript, no Python/Rust FFI) as a forced-alignment step run server-side immediately after each TTS generation returns. Align the cleaned, joined snippet text against the returned audio, then derive a new `AudioSnippet` record per source snippet with word-level timestamps and a millisecond offset range into the shared generation audio. Snippets stop being "grouped by generation" for playback purposes once alignment succeeds — each snippet's `AudioSnippet` becomes the actual unit of playback, selection, and splice-regeneration.

## New Dependencies

- `echogarden` — forced alignment, added to `package.json` dependencies.
- `uuid` (or equivalent) — Node's built-in `crypto.randomUUID()` only produces v4; deterministic v5 IDs require the `uuidv5` function specifically, which Node's `crypto` module does not expose natively. Add the `uuid` npm package for `uuidv5`.

## Data Model Changes (`src/types.ts`)

```ts
export interface WordTimestamp {
  word: string;
  startMs: number;
  endMs: number;
}

export interface AudioSnippet {
  id: string;            // uuidv5(name: generationId, namespace: snippet.id) — deterministic, re-derivable
  snippetId: string;
  generationId: string;
  startMs: number;        // offset into the shared generation audio
  endMs: number;
  words: WordTimestamp[];
}
```

- `Generation` gains an optional `alignmentStatus?: 'pending' | 'done' | 'failed'` so the UI can distinguish generations that predate this feature (or failed alignment) from ones with usable `AudioSnippet`s.
- `Snippet` gains an optional `audioSnippetId?: string | null` pointing at its current `AudioSnippet`, parallel to the existing `activeGenerationId`.
- No existing fields are removed. A `Generation`/`Snippet` with no `AudioSnippet` falls back to today's whole-generation playback behavior exactly as now — this is additive, not a breaking migration.

## Server-Side Pipeline (`server.ts`, near `/api/tts/generate`)

1. After TTS audio returns successfully (existing code path, `audioData`/`resMimeType`), if the request covered one or more real `Snippet`s (not a raw ad-hoc preview), run alignment:
   a. Build the same joined text used for the TTS request, but stripped of inline direction tags (`/\[[\w ]+\]/g`) — directions are performance notes, not spoken words, and would otherwise desync the alignment.
   b. Call `echogarden`'s forced-alignment API against the decoded PCM audio and the cleaned text.
   c. Walk the alignment result's word timings and match them back to each source snippet's cleaned text span (snippets were joined in a known order with known boundaries, so this is a straightforward cumulative-offset walk, not fuzzy matching).
2. For each snippet in the request, construct one `AudioSnippet`:
   - `id = uuidv5(generationId, snippet.id)` — snippet UUID as namespace, generation ID as name. Deterministic: re-running this on the same snippet+generation pair (e.g. re-importing a sidecar) always reproduces the same `AudioSnippet.id`, so re-processing is idempotent rather than duplicating records.
   - `startMs`/`endMs` from the first/last aligned word belonging to that snippet.
   - `words` from the aligned word list within that range.
3. Return `audioSnippets: AudioSnippet[]` alongside the existing generation response payload. Set `Generation.alignmentStatus` to `'done'` on success, `'failed'` on alignment error (TTS audio/generation itself still succeeds and remains usable via the old whole-generation path either way — alignment failure is never fatal to generation).

## Client-Side Changes

- **`dbService.ts`**: no schema change needed — `AudioSnippet`s reference the same `Generation.id` audio blob already stored under that key in IndexedDB; only a byte offset is added at the metadata layer. Playback/export slice the existing decoded PCM buffer using `startMs`/`endMs` rather than fetching separate audio.
- **Playback (`App.tsx`)**: `playSnippetAudio`, `playSnippetAudioById`, `playFromSnippetById` check for `snippet.audioSnippetId` first; if present, seek/slice audio playback to that `AudioSnippet`'s `startMs`–`endMs` range instead of playing the full generation. Falls through to current whole-generation behavior when absent.
- **`generationGrouping.ts`**: grouping by shared `activeGenerationId` remains as the *display* grouping for generations without alignment; once a generation has `alignmentStatus: 'done'`, individual snippets can be shown/played/exported independently without needing to change how they're visually grouped (grouping is a display concern, not a playback-mechanism concern going forward).
- **Splice-regeneration**: regenerating a single snippet within an aligned group produces a new standalone generation covering just that snippet (already supported by the existing per-snippet generation path); the surrounding snippets' existing `AudioSnippet`s are untouched, so the "splice" is really just "this one snippet now points at a different, smaller generation" — no audio stitching required at generation time, only at export time (existing per-scene/per-chapter/full-project export concatenation already handles multi-generation stitching).

## Sidecar Import (`sidecarImporter.ts`)

- On importing a legacy `.absproject.audio.json` sidecar, run each restored `Generation` through the same clean → align → derive-`AudioSnippet`s pipeline used for live generation, rather than treating import as a special case. Because `AudioSnippet.id` is deterministic, re-importing the same sidecar multiple times reproduces identical `AudioSnippet` records instead of creating duplicates.
- Alignment on import can be slower/batched (no user waiting on a live generation), so this can run as a background pass after the base import completes, updating snippets incrementally rather than blocking the "import successful" message.

## Staged Implementation & Testing (TDD, per step)

1. **Add `echogarden` + `uuid` dependencies.** Verify install succeeds, no build breakage. No behavior change yet.
2. **Write failing tests for the text-cleaning + snippet-boundary-splitting logic** (a pure function, testable without touching echogarden or audio at all): given joined cleaned text + a mock word-timing array, correctly partition timings back into per-snippet ranges. Implement until green.
3. **Write failing tests for deterministic `AudioSnippet.id` generation** (same generationId + snippetId always yields the same id; different inputs yield different ids). Implement `uuidv5` wrapper until green.
4. **Wire real `echogarden` call server-side** behind the existing `/api/tts/generate` success path; manually verify against a real generation that alignment output looks sane before trusting it in the pipeline (no existing test coverage can substitute for actually listening to a few aligned words for accuracy).
5. **Client playback**: extend `playSnippetAudio`/`playSnippetAudioById`/`playFromSnippetById` to prefer `AudioSnippet` offsets when present; existing whole-generation playback path stays as the fallback and needs no test changes since its behavior is unchanged.
6. **Sidecar import pipeline reuse**: extend `sidecarImporter.ts` to call the same split logic; add a test asserting re-importing the same sidecar twice produces identical `AudioSnippet` ids (no duplication).
7. **UI**: word highlighting during playback, and text-range → play-selection, layered on top of `AudioSnippet.words` once the above is solid and confirmed accurate on real content.
