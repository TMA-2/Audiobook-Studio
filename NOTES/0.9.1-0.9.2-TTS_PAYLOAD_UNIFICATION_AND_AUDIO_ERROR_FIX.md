# 0.9.1-0.9.2 TTS Payload Unification & Audio Error Fix Plan

## Overview
This plan addresses the cleanup and simplification of text-to-speech (TTS) request parameters between client callers, `geminiService.ts`, and `server.ts`, while resolving the cryptic `Audio playback error: { "isTrusted": true }` console logs caused by unhandled DOM Event objects in `audioService.ts`.

## Planned Changes

### Step 1: Fix Audio Playback Error Handler in `src/services/audioService.ts`
- Inspect `audio.error` (`MediaError`) inside `audio.onerror`.
- Prevent spurious alerts when playback is interrupted/stopped intentionally (`MEDIA_ERR_ABORTED`).
- Extract descriptive error messages/codes instead of passing the raw DOM `Event` object to `console.error`.

### Step 2: Unify `generateTTS()` Parameters in `src/services/geminiService.ts`
- Update `generateTTS` function signature to take `speakers: Array<{ name: string; voice: string }>` as the primary speaker parameter.
- Validate that `speakers.length` is either 1 or 2 (throw an explicit error if empty or > 2).
- Send the unified `speakers` array in the JSON payload to `/api/tts/generate`.

### Step 3: Simplify Server Backend Endpoint in `server.ts`
- Normalize `req.body.speakers` in `/api/tts/generate`.
- Configure `speechConfig` seamlessly:
  - If 1 speaker: pass single `voiceConfig` with `requestSpeakers[0].voice`.
  - If 2 speakers: pass `multiSpeakerVoiceConfig` with mapped speaker names and prebuilt voices.
- Maintain Stroustrup brace formatting and basic JSDoc comments across endpoints.

### Step 4: Update All Caller Sites in `src/App.tsx`
- `handlePreviewVoice`: Pass `[{ name: speaker.name, voice: speaker.voice }]`.
- `handleGenerateSnippet`: Pass `uniqueSpeakers.map(sp => ({ name: sp.name, voice: sp.voice }))`.
- `handleBulkGenerate`: Pass `uniqueSpeakers.map(sp => ({ name: sp.name, voice: sp.voice }))`.

### Step 5: Verification & Documentation
- Run `npm run lint` and `compile_applet` to confirm type safety and build success.
- Bump version to `0.9.2` in `package.json`.
- Update `CHANGELOG.md` under `[0.9.2]`.
