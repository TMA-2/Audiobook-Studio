# Streaming Sidecar Export Implementation Plan

## Overview
Currently, `handleExportSidecar()` loads all audio generations from IndexedDB simultaneously into an in-memory array (`generationsList`) before calling `JSON.stringify()` and creating a `Blob`. For large projects, this causes high memory consumption.

This plan introduces a streaming export mechanism using the Web File System Access API (`FileSystemWritableFileStream` via `window.showSaveFilePicker()`). This streams JSON headers, audio record chunks, and JSON footers directly to the destination file on disk without retaining all audio base64 buffers in memory.

## Proposed Changes

### 1. `src/utils/sidecarExporter.ts`
- Implement `exportSidecarStream()` function:
  - Check if `window.showSaveFilePicker` is supported.
  - Prompt user for output file location using `showSaveFilePicker({ suggestedName, types: [...] })`.
  - Obtain a `FileSystemWritableFileStream` (`handle.createWritable()`).
  - Write JSON opening bracket and metadata headers.
  - Stream each audio generation sequentially from IndexedDB (`getAudio()`), format JSON chunk, and call `writable.write(chunk)`.
  - Close writer (`writable.close()`).
  - Fallback logic: If `showSaveFilePicker` is unavailable or rejected by browser policy/iframe sandbox, assemble chunks into a sequential Blob array with progress feedback before triggering download.

### 2. Integration in `src/App.tsx`
- Replace in-memory array concatenation in `handleExportSidecar()` with `exportSidecarStream()`.
- Provide progress feedback during sidecar export.
