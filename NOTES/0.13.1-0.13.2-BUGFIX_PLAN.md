## 1. Raw char/word count in generation log

- Cause: `handleBulkGenerate` in `src/App.tsx` maps selected snippets with a braced callback and no `return`. Every element is `undefined`, so `rawText` is only newlines.
- Fix: extract a pure `computeRawTextStats(snippets)` helper that trims, joins with `\n`, and returns `{ chars, words }` (0 words for empty text). Use it in `handleBulkGenerate` and `handleGenerateSnippetAsync`.
- Test: helper counts for normal text, empty text, and whitespace-only snippets.

## 2. Chapter header prompt chars / words / overhead

- Cause: the header sums raw text over the whole selection or whole chapter. `compilePrompt` builds the prompt from a different set: the first selected snippet in `individual` mode, the first scene or first 10 snippets in combined mode, capped at 2 speakers / 8000 chars. Overhead can be negative.
- Fix: use `compiledRes.targetSnippets` for the raw counts through the same helper as item 1, so raw and prompt describe the same snippets.
- Test: with a selection of N snippets in `individual` mode, raw counts cover only the first. Overhead >= 0.

## 3. Snippet editor input lag

- Cause: to be confirmed. Each keystroke calls `onUpdate` and rewrites project state. This re-renders the whole chapter, runs `compilePrompt` in the header, and triggers autosave (`JSON.stringify` of the project at `App.tsx` ~244).
- Plan: measure first with the React Profiler. Then keep the textarea value in local state, commit to project state after ~300 ms idle and on blur or unmount, and wrap the snippet row in `React.memo`.
- Test: hook test that rapid changes produce one commit, and blur flushes immediately.

## 4. Sheets log overwrites one row

- Likely cause: `appendGenerationLogToSheet` omits `insertDataOption`. The default is `OVERWRITE`, which writes into the next empty cell of the detected table and can overwrite existing rows.
- Fix: add `insertDataOption=INSERT_ROWS` to the append URL.
- Test: `tests/sheetsService.test.ts` asserts the request URL contains it. To be confirmed against your sheet after the fix.

## 5. getAudioDuration errors

- Cause: Gemini returns `audio/l16; rate=24000; channels=1`. The mime check only matches `pcm`, `wav`, or empty, so the call falls to `new Audio()`, which does not exist in Node. `playAudio` also hard-codes 24000 Hz for raw PCM.
- Fix: treat `l16` as raw PCM and read `rate=` from the mime string, in both `getAudioDuration` and `playAudio`.
- Test: `getAudioDuration` on a known-length L16 buffer returns the expected seconds at a given rate.
- Open: the client "Audio playback error" log has no confirmed trigger yet. I'll check whether `stopAudio()` on the previous element fires `onerror`, once the L16 fix is in.
